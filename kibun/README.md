# Kibun

料理をめくりながら、今日の気分で一皿を決める Web アプリ。

- 写真を左右にスワイプ（または ← → キー / 下のボタン）。右で「候補に入れる」、左で「見送る」
- 候補に入れた料理に近いものが出やすくなる。ただし同じ形の料理（麺・甘いもの…）は3連続にならず、数枚に一度「寄り道」が混ざる
- 候補一覧から「これにする」、または「二つずつ比べて決める」で一皿に絞る

```bash
npm install
npm run dev           # 開発サーバ（LAN 公開）
npm run build         # 型チェック + 本番ビルド → dist/
npm run check         # 型チェック + 推薦ロジックのテスト
npm run check:photos  # 全料理の写真 URL が画像を返すか確認
```

## 設計

**ランタイム依存ゼロ**。Vite + TypeScript + 素の DOM。ビュー4枚とスワイプ1つにフレームワークは要らない。ビルド後は JS 22 kB / CSS 6 kB（gzip 9.7 kB / 2.2 kB）。

```
src/dishes.ts     料理カタログ（タグ・説明・写真ID・写真の代表色）
src/recommend.ts  セッション内の気分から次の一皿を選ぶ（純粋関数、テストあり）
src/store.ts      セッション状態（sessionStorage）、undo
src/photo.ts      画像 URL / srcset、読み込み前・失敗時の表示
src/views/        deck（スワイプ）・shortlist（候補）・compare（二択）・today（決定）
```

### 推薦：恒久的な好みではなく「今の気分」

- 各料理は「料理圏（和・中華…）」「形（麺・ごはんもの…）」「性格（こってり・辛い・温かい…）」のタグを持つ
- 気分ベクトル = このセッションの行動の合計。候補に入れる +1、見送る −0.18（見送る理由は様々なので弱く）、候補から外す −0.5。古い行動ほど 0.9 倍ずつ薄れるので、途中で気分が変わっても追従する
- 次の一皿 = 気分との一致度 − 直近3枚との似すぎペナルティ + 少しの揺らぎ。さらに直近2枚と同じ「形」は3枚目にしない
- 3〜5枚に一度「寄り道」：気分と逆寄りの帯から、候補のどれとも似ていないものを選ぶ。強く避けられている下位2割は選ばないので、ただの嫌いなものにはならない
- まだ何も候補に入れていない最初は、料理圏が散らばるように配る
- 状態は sessionStorage だけ。タブを閉じれば忘れる。日をまたいで好みを学習しないのは意図的
- 画面上部の一行（「麺の気分が続くなら　ラーメンから」「ここで寄り道」）で、なぜこの料理が出たかがわかる

### 画像

- 表示中の1枚と、その下に控える次の1枚だけを読み込む（現在の1枚は `fetchpriority=high`、次の1枚は `low`）。以降は1操作につき1枚
- CDN 側で 4:5 にクロップし、AVIF/WebP を自動選択。`srcset` は 240〜1280px の5段階なので、一覧のサムネイルは 240/400px、スマホの本画像は 960/1280px だけを取りに行く
- 読み込み前は写真の代表色で塗っておき、読み込み後にフェードイン。写真が無い・失敗した料理は、その色の上に料理名を縦組みで置いた表紙になる
- Web フォントは使わない（和文フォントは写真数枚分より重い）。見出しは端末の明朝体

### デザイン

カード・枠線・角丸・影の箱を使わない。階層は文字サイズ、明朝とサンセリフの組み合わせ、余白で表す。写真は画面幅いっぱいに置き、ボタンは文字だけで「候補に入れる →」を太字にする。

## 写真について

写真は Unsplash の photo ID で参照しています（`src/dishes.ts`）。開発環境のネットワーク制限で画像 CDN に接続できなかったため、**ID と料理の対応は実際の画像で確認できていません**。`npm run check:photos` で全 URL の読み込みを確認し、ブラウザで目視して、合わないものは ID を差し替えてください（`photo` を消せば表紙表示になります）。親子丼・とんかつ・天ぷらそば・焼き魚定食は確かな ID がなかったので、最初から表紙表示です。
